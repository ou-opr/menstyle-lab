## 逐条细节

### 1. 测试只证明数据层（原「最大的工程风险」）

**问题本质**：1300+ 断言全在 Node 里跑纯函数，57 个文件里 37 个从未被加载，
其中包含 `App.jsx`、全部 React 交互、3D 场景、备份恢复 UI、移动端导航。
「数据层正确」被证明了，「产品能用」没被证明。

**做法**：
- 新增 `e2e/smoke.spec.js`，5 条用例 × 2 个 project（desktop / mobile）= **10 条**：
  1. 打开页面：10 个章节齐全 + 3D canvas 非零尺寸 + 评分卡出数字
  2. 换装：点衣柜单品后造型 chip 与评分都更新
  3. 记日历：写入 localStorage 且日历区可查到
  4. 备份往返：加单品 → 重置 → 写回快照 → 刷新后数据仍在
  5. 移动端导航：无横向溢出 + 导航可横滑 + 锚点可达 + 触控目标达标
- 覆盖率分母改为「被测试实际加载过的文件」：**91.97%（4213/4581）**，阈值 41 → **50**。
- 未加载文件数保留独立闸门（`--max-never-loaded=40`），不让它伪装成覆盖率下降。

> 口径说明：全量口径仍是 41.18%（4213/10231），因为 UI 组件层不进 Node 覆盖率。
> 它的真实意义由 E2E 承担——两条线各管一半，不再用一个数字假装全权负责。

**实测**：本地 `npx playwright test` → 10 passed；GitHub Actions 的 E2E job → success。

### 2. CI 是死文件

**做法**：
- `gh repo create menstyle-lab --private` 建成私有仓库，推送到 `origin/main`。
- 首次推送就验证了 pre-push 门禁真的在拦（日志：`[pre-push] 回归网通过，允许推送`）。
- CI 跑起来后 4 个 job：Regression(node 20) / Regression(node 22) / Coverage / **E2E smoke (Chromium)** / Source freshness — **全部 success**。

**顺带做了**：`useCrossTabSync` —— 监听 `storage` 事件，多标签页改动会互相重读，
不再「后写的一方静默覆盖先写的一方」。

**门禁真的会红吗？** 三层都验证过：

| 层 | 验证方式 | 结果 |
|---|---|---|
| pre-push | 把 `wearCount +1` 改成 `+0` 后 `git push` | **被拒**，坏代码没到 GitHub |
| CI（绕过 pre-push） | `SKIP_TESTS=1 git push` 到临时分支 | **CI failed**（run 39051161769），随后删分支 |
| 覆盖率门禁 | 自检用例「测试全红 + 覆盖率 100% → 必须 FAIL」 | **exit 1**（修复前会误判为 0） |

> ⚠️ 仍有一条限制：pre-push 只在执行 `npm run hooks:install` 的机器上生效，
> 这是 git hooks 的固有性质。CI 才是跨机器的那一层，所以现在远程是必须的、也在真的跑。

### 3. 天气分偏挤

**问题本质**：`partRain` / `partWind` / `partIndoor` / `partCommute` 全是「命中即满分」的布尔判断——
不下雨一律 20 分、有外套一律 15 分。结果全库只有 5~7 个取值、70.8% 满分，
而 `TodayPlanner` 拿它给「今日三套」排序——**全都满分等于没有排序**。

**做法**：
- 非降水天不再白送满分：按「这套遇上雨有多糟」预扣（帆布鞋 -2、无外套 -1）。
- 挡雨层按外套保暖度分 3/7/10 三档，不再「有外套就满分」。
- 挡风按保暖度分 7/10/13/15 四档；室内按保暖度连续扣分；通勤补 w3 档。
- 内搭厚度影响淋湿后的恢复难度（无外套 + 厚内搭 -2）。

**实测（16848 组合）**：

| 场景 | 修前取值数 | 修后取值数 | 修前满分率 | 修后满分率 |
|---|---|---|---|---|
| 20℃ 晴 / 微风 / 步行 | 7 | **18** | 70.8% | **10.5%** |
| 8℃ 雨 / 大风 / 地铁 | — | **42** | — | 0% |
| -2℃ 雪 / 大风 / 步行 | — | **42** | — | 0% |

新增 6 条分布断言（取值数下限、满分率上限、分项梯度单调性），改回通胀立刻变红。

### 4. 产品边界

README 新增「能力边界」表格，明确写清：

- **纯本地**：无账号、无云端、无多设备同步（换设备靠手动导出导入）；
- **多标签页**：已做 `storage` 同步，但**不做冲突合并**，以最后写入为准；
- **3D**：风格化程序化模特，用于看配色与比例，**不是写实版型拟合**；
- **单品**：59 件程序化参考坐标，**不是可购买商品**（无价格/库存/购买链接）；
- **推荐**：基于规则的可解释评分，**不是机器学习**，不学习身材数据；
- **资源库**：187 条人工调研，链接会失效，页面显示最后验证时间。

### 5. 体积与移动端

**字体（最大单项）**：609 KB → **152 KB**，两条独立优化：

| 手段 | 效果 | 说明 |
|---|---|---|
| 可变轴实例化 | 609 → ~317 KB | 项目只用 400/700 两个字重，整条 wght 轴白占一半字节 |
| 按「实际渲染字符」裁剪 | 317 → **75 KB/字重** | 源码里有 1712 个汉字，衬线字体实际只渲染 **211 个**（正文走无衬线） |

配套：`scripts/collect-serif-chars.mjs`（无头浏览器采集实际渲染字符）+
`build-font-subset.py --check-only`（断言「页面渲染字符 ⊆ 字体 cmap」，缺字即失败）。
找不到浏览器时自动回退源码字符集，不会静默产出错误子集。

**单文件版**：3.74 MB → **3.13 MB**；全部资源 gzip 合计 2068 KB → **1614 KB**。

**触控目标**：从「只覆盖 7 个类名」改为兜底规则，但踩到一个坑——
`@media (pointer: coarse)` 在部分设备/模拟器上不生效（实测 Playwright Pixel 5 里为 false，
203 个目标仍是原尺寸）。改用 `any-pointer: coarse` + 窄屏宽度双条件，
并用 `!important` 压过组件内 `.td-chip{min-height:32px}` 这类声明。
行内文字链接按 WCAG 2.5.8 例外条款保留原尺寸（强制 44px 会把段落撑碎）。

**剩余诚实说明**：触控目标按 44×44 达标，但**仍未到 60px 的 Material 舒适标准**；
密集控件（星级评分、日历格子）按规范例外保留 32px / 行高。

## 仍然存在的限制（不掩饰）

1. **行覆盖率全量口径只有 41.18%**：UI 组件层不进 Node 覆盖率，靠 E2E 的 10 条路径覆盖主流程，
   但不是逐行覆盖。真正的「UI 全覆盖」需要组件级测试（jsdom + testing-library），本轮没做。
2. **E2E 只有 10 条冒烟**：覆盖主流程，不覆盖边界（离线、配额超限、坏备份包、3D context lost）。
   这些目前由单元测试或手工验证兜底。
3. **pre-push 依赖本机安装**（`npm run hooks:install`），换机器需重跑；跨机器保证靠 CI。
4. **无冲突合并**：两个标签页同时改同一份数据时以最后写入为准，已在 README 写明。
5. **字体缺字风险**：子集按「当前页面渲染字符」生成。新增文案若引入新汉字，
   `--check-only` 会报缺字，但需要人工重跑 `font:build`（已在 README 与脚本里写明流程）。
